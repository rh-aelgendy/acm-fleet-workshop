= ACM Fleet Operations Workshop

A growing organization has clusters in several locations. Its platform team needs one place to discover workloads, apply controls, choose deployment destinations and investigate failures. Payments developers need a bounded way to request applications and cloud access.

This workshop follows that story using Red Hat Advanced Cluster Management (ACM), OpenShift GitOps and optional cloud integrations. You make decisions in the ACM and OpenShift consoles, inspect the resulting YAML and verify controller outcomes.

== Learning outcomes

* Explain hub/agent responsibilities, cluster sets and placement decisions.
* Find a workload across the fleet and distinguish availability from compliance.
* Enforce a namespace baseline and demonstrate a local admission rejection.
* Deploy applications with central Argo CD push reconciliation and dynamic ACM selection.
* Prepare a second destination, inspect controls and move stateless demo traffic.
* Investigate a failure and discuss resource requests using observed metrics.
* Explain bounded team delegation and the cloud-specific dependencies of self-service.

== What this workshop does not assume

A second region does not change the placement model, but latency, egress, quotas, storage and connectivity still matter. An AKS cluster is not interchangeable with OpenShift for labs that need Routes, SCCs, OLM, GitOps integration or supported observability collectors. Consult xref:appendix-compatibility.adoc[Compatibility and module gates].

The mobility gateway is workshop integration, not native ACM traffic management. The three-tier database demonstrates local persistence, not storage replication. Cloud request contracts are custom examples, not a built-in ACM service catalog.

== Guide conventions

* *Action*: perform a named console operation in the stated cluster and namespace.
* *Expected*: verify observable evidence before advancing.
* *Value*: explain the customer outcome.
* *Fallback*: complete the safe subset or record the blocker; do not claim success.
* *Checkpoint*: capture the selected scope and result without credentials.

This is a community workshop, not an official product certification or support statement. The guide uses Antora/AsciiDoc and the Showroom theme. Product support is determined by the applicable Red Hat support matrix.
