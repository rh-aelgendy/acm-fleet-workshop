= Facilitator preparation

== Keep installation out of the participant flow

Preparation may use CLI automation. During the workshop, participants make fleet decisions in ACM, inspect YAML in the correct console and follow ACM links into Argo CD. This preserves the distinction between product capability and custom integration.

== Current preparation code

The presenter repository contains `config/demo.yaml`, `scripts/preflight.sh`, `scripts/setup.sh`, module-specific setup scripts and ownership-aware reset/teardown routines. Its existing `docs/facilitator-runbook.md` remains the operational reference for the original fleet.

For another environment, work on a separate checkout/configuration and inspect the scripts' assumptions first. The documentation questionnaire does not modify `config/demo.local.yaml` or cloud settings. Do not copy credentials into the guide or Git.

== Fresh-environment work still requiring rehearsal

* Confirm cluster-name substitutions reach every prepared Placement, GitOps destination, gateway URL and optional-module template.
* Validate the chosen ClusterSet and ClusterSetBindings without moving unrelated clusters.
* Verify Argo access to private APIs, controller inventory permissions and namespace bootstrap.
* Choose region/storage/provider values and optional-module versions from supported combinations.
* Verify generated workload identities and cloud scopes; do not reuse the original fleet's IDs.
* Exercise every cleanup path against owned resources only.

== Release gate

Do not call this universally reproducible until the xref:appendix-validation.adoc[acceptance checklist] passes on a fresh hub and spoke. Build and link checks prove the guide renders; they do not prove infrastructure readiness.

== Focused one-hour preparation

Follow xref:session-60-minutes.adoc[the session gates]. Prepare Payments before approved access. Choose the existing-request track to retain provisioned identity evidence. Preparing a fresh request is a backstage operation that withdraws real Azure access dependencies; wait for AwaitingRequest / NotRequested before the audience arrives. Do not reset Payments afterward, since that can reset the extension. Do not run a global reset simply to review documentation.

Verify browser logins for hub, GitOps Route and private spoke, named Perses tiles, the production selection label and the canary/reporting opening state. Configure and test a human SSO group separately if presenting developer isolation. Keep placeholder annotation and cluster provisioning exercises outside this hour. Restore only changed module state afterward.
