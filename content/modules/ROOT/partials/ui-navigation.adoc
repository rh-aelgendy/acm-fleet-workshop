In the ACM fleet perspective, use *Infrastructure → Clusters*, *Search*, *Governance* and *Applications*.
For hub resources, use *ACM → Search* with `kind:<resource-kind> namespace:<namespace>`. Select the hub result and open its resource details/YAML. Verify the cluster and namespace before editing. If the kind is not indexed or the resource cannot be opened, use read-only CLI inspection; do not interpret a missing Search result as an absent resource.
For a spoke resource, follow *ACM → Infrastructure → Clusters → cluster → Console*. A hub YAML editor does not edit a spoke.
Argo CD handles sync and resource trees; ACM supplies fleet context. Menu wording varies with installed plugins.

IMPORTANT: Private APIs and ingress require browser/controller network access. An ACM login alone does not provide it. Use indexed resource details when the managed console is unreachable; do not claim an unapplied change succeeded.

Open Argo CD through *hub console → Networking → Routes → {gitops-namespace} → openshift-gitops-server → Location*. The presenter fleet’s ACM Applications list exposes View/Edit/Search/Delete; do not assume it has Sync or an Argo link. ApplicationSet rows and generated Application names differ. Use Search for `kind:Application namespace:{gitops-namespace}` or the signed-in Argo list.

For PlacementDecision, match `metadata.labels.cluster.open-cluster-management.io/placement` to the intended Placement and inspect all matching shards. Objects live on the hub; `status.decisions` names the target clusters.
